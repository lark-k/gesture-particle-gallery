# 相册集

## 使用流程

登录 → 相册集列表 → 创建 / 选择相册 → 翻书进入沉浸式画廊 → 在当前相册上传照片。画廊左上方可返回列表；刷新 `/albums/:id` 可直接打开有权访问的相册。未登录继续显示公开示例空间。

首页最多展示前三本，一本居中、两本并排、三本一大两小；手机窄屏纵向排列。第四本起位于下方：仅多一本或两本时自然排列，三本及以上采用中间突出、两侧预览的轮播，支持按钮与横向滑动。编辑时可将相册放到首位；名称搜索覆盖全部相册。

封面可使用六种内置素材，也可使用当前相册的任意已上传照片，左右 / 上下滑杆调整取景。首次创建先选内置封面，进入上传后可再次编辑。名称最多 60 字、简介最多 240 字。

悬停时封面绕左侧书脊打开约 42°、露出照片内页，同时整本书轻微抬升并跟随指针倾斜；移开后闭合。进入时书本移至屏幕中间、封面打开约 155°，待画廊环境与首张照片就绪后推进并淡入画廊；空相册等待环境即可。加载失败可重试或返回，准备超过 15 秒显示提示。系统减少动态偏好关闭窗影和悬停动态，并将进入转场改为短淡入；隐藏标签页停止背景动画。

## 存储与接口

`albums` 保存用户归属、名称、简介、预设封面、照片封面 ID、取景位置和展示顺序。`photos` 与 `uploads` 增加 `album_id`；数据库触发器要求照片和上传任务归属同一用户的有效相册。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/albums` | 列表及账户总照片数 / 新建 |
| GET / PATCH / DELETE | `/api/albums/:id` | 详情 / 更新 / 删除相册及照片 |
| GET | `/api/albums/:id/photos` | 当前相册照片 |
| POST | `/api/albums/:id/feature` | 放到列表首位 |
| POST | `/api/uploads/authorize` | 必须传入 `albumId`，完成上传使用授权时的相册 |

所有接口沿用现有会话、账户检查和来源校验。照片封面限定属于当前相册，跨用户请求返回 404；账户总配额包含所有相册的照片与有效上传预约。原 `/api/photos` 保留账户范围读取兼容，画廊使用相册专属接口。

SQLite 自动迁移在事务内增加结构。每个有旧照片或待完成上传的用户获得一个「默认相册集」，原照片 ID、对象路径与上传任务保持不变，重复启动不会重复创建。

删除操作先在一个事务内移除相册、照片元数据和上传凭证，并将对象路径写入持久化 `storage_cleanup` 队列，再执行 OSS 删除。正在校验上传时返回 409；对象删除失败会保留队列，在下次列表请求、删除操作或服务器启动时重试。已签发的短时读取地址在对象删除完成或授权过期前可能仍可用。

未配置 OSS 的开发模式中，相册信息保存于 SQLite；照片和照片封面仅在当前页面会话保留。切换相册保留这些本地照片，刷新或退出清除。生产模式仍要求完整 OSS 配置。

## 验证

`npm test` 覆盖旧库迁移幂等、归属隔离、固定上传目标、跨相册总配额、封面校验、排序、删除与对象清理重试。`npm run build` 包含 TypeScript 检查。浏览器视觉与交互验证使用独立内存数据库和本地模拟存储，不连接用户的 SQLite 或 OSS。
